# NEG archetype & Manifestation observability audit

**Date:** 2026-08-30 · **Tree:** `enemy-world-work` @ `b2b1604` (HEAD `f14868a` differs only in `docs/audits/*`; every citation re-verified there) · **Kind:** read-only observability audit (nothing modified).
**Scope contract:** for the three NEG archetype augments, all 18 Manifestation rules and all 10 pairs — what the player can see, what the Run Sheet explains, what is invisible, and what correct behaviour could be mistaken for a bug. No rebalancing, no redesign; every fix noted surfaces an existing truth through an existing mechanism. Findings already ranked in `docs/audits/2026-08-28-run-sheet-completeness.md` ("prior") are referenced by row, never re-ranked; §5–§6 rank only what is new.

**Path key** (two scout notes had wrong paths): singles `effects/manifestations/logic/*.gd`; pairs `effects/manifestations/pairs/*.gd`; base class `core/systems/manifestations/ManifestationEffect.gd`; burden `core/systems/items/BurdenResolver.gd` / `BurdenSnapshot.gd`; stat pass `core/actors/player/player.gd:481-604`; sheet `ui/widgets/RunSheetHUD.gd`; tooltip `ui/widgets/ItemTooltip.gd`.

## 0. Shared plumbing (applies to every row below)

- **Two gates in front of every explanation.** The Run Sheet exists only while the bag is open (`ui/screens/hud.gd:331-336`), refreshed at 10 Hz (`:150-155`); BURDEN ledger, rule boxes and pairs live on the third tab (default tab is PROFILE, `RunSheetHUD.gd:41,68-74`). Every rule and pair `popup()` (`ManifestationEffect.gd:231-240`) goes to `BattleText.popup`, which returns early when Settings "Show ability and Manifestation callouts" is off (`core/combat/BattleTextRenderer.gd:66-70,129`; label `ui/screens/settings/SettingsScreen.gd:292`). Survivors: world-space `_draw()` overlays, the HUD noun row (a Control, deliberately un-gateable — `ui/controllers/HudManifestationController.gd:154-156`), the pair notifier card, `tutorial_tip`, and the sheet.
- **Rule text is live.** Tooltip (`ItemTooltip.gd:202` via `ManifestationCatalog.describe`) and sheet (`ManifestationRunner.gd:778-793` singles, `:299-315` pairs) render `effect.describe()` with this instance's potency. The static catalog `rule` strings are fallback only; `docs/current_game_data.md` paraphrases them (condensed, not verbatim — singles and pairs alike). A describe() error is a live UI lie; a catalog-line error is doc drift.
- **Burden chain.** `BurdenResolver.resolve` (`:47-110`): polarity census over all 8 slots (`:64-67`); entries only for statistical slots 0-5 (`:68` skips `slot >= Inventory.STAT_SLOT_COUNT`); worst slot by strict `>` (`:80-82`); exactly one suppression, runtime only (`:87-92`); totals over ACTIVE burden only (`:96-107`); qualifying = `ratio >= 0.10` of the item's authored `pct_min` range (`:39-45`; `BurdenSnapshot.gd:32`). Engine `player.gd:570-576`; Doctrine `:582-587`; Lens luck kicker `:593-595`.

### 4.2 Announcement-gating finding

The layer's *structural* announcements are un-gated Controls (noun row/flash/pulse, pair GAINED/LOST card, ×2 tip, intro card, sheet); its *firing* feedback is entirely `popup()` behind `callouts_enabled()` (`BattleTextRenderer.gd:66-70,129`). With the checkbox off a Manifestation build keeps its structure and loses every fire line; the un-labelled world-draws are all that remain, and Death Rattle's health cost becomes fully invisible self-damage. Seven rules/pairs are popup-less even with callouts on (§2, §3 tallies). Signal census for this scope: `RunEvents` carries no burden or suppression signal at all; `power_threshold_noted` (`ThreatDirector.gd:171,244`) and `segment_phase_changed` (`SegmentProcBuilder.gd:519-520`) have no UI consumer (prior #5, #6).

## 5. Ranked: most likely mistaken-for-bug moments (new to this audit)

Each: what the player experiences → what is actually happening → minimal surfacing fix using only existing mechanisms. Not re-ranked here because prior §4 already covers them: Engine share missing from PROFILE (C19 → #1), Sigil/Overtime/Anchor/Fever/Martyr multipliers not moving POW/HST (→ #2), Doctrine pick-time text teaching the absolute rule (D13/D19 → runner-up), weaker enemies after a 3rd rule (→ #5), Lens Luck total (L18 → #8).

1. **"The Lens isn't working — the slot still says −80."** (L12) The value label prints the stored roll; suppression is runtime-only and the slot is contributing +44%. Fix: `InventorySlotView` reads `player.last_burden.is_suppressed(slot)` (already exposed for the tooltip) and prints `+inverted_return(severity)` in the positive tint, matching the sheet's Lens line.
2. **"My second ring didn't light the pair — and the sheet lists the rule twice."** (P11) Distinct-rule counting; per-instance sheet boxes. Fix: append "A duplicate rule does not add a second ◆ — it ranks the rule up" to the existing duplicate line (`ItemTooltip.gd:203`); collapse sheet boxes by `definition.id` with a "×2" suffix (ids are already in `get_active_summaries`).
3. **Stats drop on a pickup.** (L15 + C16) Lens retarget snaps the old curse's penalty back; the Engine auto-feed deepens the worn roll. Both recompute silently. Fix: the feed toast (`ItemPickup.gd:299-304`) appends "deepened to −N%" when the Engine is owned; for the retarget, the stat pass overwrites `last_burden` at `player.gd:530` with the previous snapshot still in hand and runs on every inventory change (`scenes/game.gd:110-116` → `recompute_run_stats`) — diff `suppressed_slot` there and emit a `tutorial_tip` "LENS: Health curse returns — Power curse inverted". Not the sheet's 10 Hz refresh: `hud.gd:190-195` only forwards to `RunSheetHUD.refresh`, which returns unless the bag is open (`RunSheetHUD.gd:84-86`), so a mid-combat pickup would never be diffed there.
4. **HP falls with no enemy near, callouts off.** (Death Rattle a) The toll is written straight to `hp`, no damage number, popup gated. Fix: also emit `BattleText.player_damage(cost)` (a different gate, `damage_numbers`) so at least one setting shows it; the inward ring already draws.
5. **Comparison says the deeper curse is worse; equipping it makes me stronger.** (L13) Raw `active_pct` diff under a Lens. Fix: when `is_suppressed(slot)` or the candidate's severity exceeds `suppressed_severity`, replace the "Effect roll" row with the sheet's own phrasing ("would be suppressed → +N% returned") using `BurdenResolver.inverted_return`.
6. **"Broken Providence / Orbiting Testament never fire."** (§2 Providence a, Orbiting a) Lucky Crit chance is 0 at Luck ≤ 0. Fix: both describe() strings append the ignition condition from constants only — "Needs Luck above 0: the roll never succeeds at or below it; the cap is %d%%", quoting `LuckResolver.lucky_crit_chance` with pure arguments the way `DebtCollector.describe` already does (`:239-245`). Not the live value: describe() renders on a detached node and may read nothing but `item`, `definition`, `potency()` and `threshold_scale()` (`ManifestationCatalog.gd:359-363`), and the same tooltip serves shop and stash (C12), where `Global.run_luck` is not this run's number. The live chance belongs on the Profile LCK row, which already reads the player — append "Lucky Crit %d%%" from `lucky_crit_chance(lck_total)` (`RunSheetHUD.gd:103,122`).
7. **Third curse, no Power; "Feeding DEEPENS" on a curse the Engine ignores.** (C14, C15) `heaviest(2)`; the deepen prompt is unscoped. Fix: the Engine sheet line names the two slots (the `entries` dict already holds item refs); the feed line reads "DEEPENS — this curse is / is not among the two the Engine burns" by ranking this slot's severity in `last_burden.severities`.
8. **Heal, then the bar instantly drops.** (Scar Tissue a) 55% claw-back to Armour. Fix: a merge-keyed `progress()` line "SCAR +N ARMOUR" at claw-back time — the rule currently has zero popups.
9. **"Walking doesn't keep my Fever chain alive, but the tooltip says it counts as an attack."** (Marching Order a) `advance_beat()`, not `note_attack()`. Fix: describe() wording "advances every beat-counting rhythm you carry; it does not reset your attack clock".
10. **"My ward stops working when I run."** (Slipstream b, Reliquary b) Slipstream drops shards to the ground; the guard needs orbit > 0. Fix: Slipstream describe() appends "shards on the ground do not guard you"; Reliquary describe() appends "anything that spends the orbit drops the guard".
11. **"MOMENTUM 0%" while fully anchored.** (Anchor a) Headline channel is momentum; stability is a second channel. Fix: HUD row shows the fuller of the noun's two channels (both already come from `get_meters`).
12. **Misfortune bank ticking down.** (Bad Fortune a) Each forge withdraws one point silently. Fix: a merge-keyed "−1 MISFORTUNE → SHARD" `progress()` line beside the existing forge spark.
