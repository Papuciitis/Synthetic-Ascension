# Exact ground material cache — 18 October 2026

Native loading traces showed that the original `CompressedTexture2D.get_image()` path can block on graphics readback: one observed first layer took about 609 ms despite the surrounding frame staging. The ground array's pixels depend only on thirteen shipped source textures and their import settings. The game now loads that exact derived array instead of rebuilding it on every fresh process.

`tools/dev/BakeGroundMaterials.gd` used the original `WorldArt.prepare_ground_material_layer` algorithm through the native Intel UHD/OpenGL renderer. It saved thirteen RGB8 512×512 layers and their generated mipmaps in a losslessly compressed Godot resource. The 9,179,912-byte resource and source/import/layer hashes are committed together. Source artwork, material repeat, shader weights and ground appearance are unchanged. Direct worlds use the same cache; missing or incompatible cache dimensions retain the original builder, and routed fallback preparation still yields between layers.

The new manifest regression was first RED (0 passed / 2 failed, native exit 1), then GREEN (4 passed / 0 failed, native headless exit 0). It checks every ordered source PNG and import hash, the derived resource hash, preprocessing revision and actual startup selection. Native `TransitionResourceWarmupTest` compares every prepared layer's complete pixel buffer, including mipmaps, with a forced fresh original build. That comparison passed exactly.

The same native warmup run rendered seventeen preparation frames but had a largest gap of 259.592 ms. It therefore **failed the separate 250 ms timing assertion**: 2 passed / 1 failed, native exit 1. This is preserved as a diagnostic limit, not described as a clean timing pass. Earlier staged preparation without the derived cache also produced a clean 182.663 ms observation; the observations are not a controlled general benchmark. The cache removes runtime layer readbacks, not every texture upload, resource-loader or driver delay. Final actual-route observations are recorded in the loading audit.

Regeneration instructions and the source-art license remain with the [derived asset](../../assets/world/ground/baked/README.md). Any source PNG, import or preprocessing change requires rebaking; the source/hash test is intended to make stale derived art fail verification. A native pixel comparison is required after a preprocessing change. This artifact is not a quality reduction, and no whole-game FPS gain is claimed.
